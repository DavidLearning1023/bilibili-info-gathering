# 分析力度：三档，按议题复杂度自动调

> **一句话**：力度不是"跑多久"，是**用几根轴看这件事**。
> 加力度的正确方式是**换测量单位或换样本池**；同样的东西多读 20 条，
> 结论不会变，只会多 20 条引文。

---

## 一、为什么需要这份文件（一次真实的教训）

2026-10-26「二游超人气角色」，同一个议题跑了三轮：

| 轮次 | 做法 | 上游 | 子代理 | 用户的判断 |
|---|---|---|---|---|
| 第 1 轮 | 8 组词族、206 候选、13 条深挖、11 个子代理 | 372 | 11 | **"不够全、不够深"** |
| 第 2 轮 | **新增「42 个角色 × 1 次检索」的角色级测量** + 8 条深挖 | 141 | 8 | 认可，但仍有缺口 |
| 第 3 轮 | **39 个角色分成 11 组做画像矩阵** + 怪信号专组 + 5 个补做 | 1,596 | 15 | "满意" |

注意第 2 轮的上游调用**比第 1 轮还少**（141 vs 372），却是转折点。
它多出来的不是调用量，是一根**新轴**：从"13 条视频怎么说"变成"42 个角色的可复现量级"。

第 3 轮再换一次样本池：不再是"视频的评论区"，而是"每个角色一组画像"，
并允许单份回传放宽到 ≤1,400 token（内容从"一条视频的摘要"变成了"一个角色的画像"）。

**结论**：复杂议题缺的从来不是"再读几条"，是**换一个能容纳复杂度的结构**。

## 二、三档定义

| | **L1 速览** | **L2 深挖**（默认） | **L3 攻坚** |
|---|---|---|---|
| **什么时候用** | 用户说「简要/快速/简单了解」 | 单点议题，用户只说「在B站了解 X」 | 判档命中（见 §三）或用户说「全面/逐个/彻底」 |
| **词族** | 2–3 | 6–8（主词各不相同） | 8–12 + **矩阵轴**（主体 × 检索） |
| **候选池** | ~40 | 200–300 | 200–300 + **N 个主体各 1 次定点检索** |
| **深挖** | **不深挖** | 8–12 条 | 15–25 条 + **画像 30–40 份** |
| **子代理** | 0 | 8–12（一条一个） | **15–25**（一条/一组一个） |
| **单份回传** | — | 态度 ≤900 / 方法 ≤1,300 token | 视频摘要同上；**画像 ≤1,400 token** |
| **评论深度** | 不拉 | 60 条顶层（opinion） | 60–100 条顶层；关键主体读楼中楼 |
| **通道** | 元数据 + 搜索 | 字幕 + 评论 + 弹幕 + 图片（按需 ASR/抽帧） | 全通道 + **补做轮换样本** |
| **纠错轮** | 无 | 反证 1 轮 | 反证 + **补做轮**（证据 C/D 的主体换 BV 重取） |
| **上游请求** | ~70 | 200–500（实测中位 341） | **600–1,600**（实测 1,596） |
| **耗时** | 3–5 分钟 | 10–20 分钟 | **25–45 分钟** |
| **产物** | 对话 + md | 对话 + md + HTML + PDF | 同 L2，且 §五 必须写矩阵与升级记录 |

> 三档共用一套评级与证据标准。**L1 砍的是通道和流程，不是判据**；
> **L3 加的是轴和样本池，不是"多写点字"**。

## 三、判档：进流程之前（阶段 0 内完成，不问用户）

按顺序判断，命中任一即 **L3**：

| # | 触发条件 | 为什么它会拉高复杂度 | 出处 |
|---|---|---|---|
| 1 | **可比较的主体 ≥ 8 个**（角色 / 产品 / 城市 / 厂商 / UP 主） | 抽样讲不清"谁更"，只有矩阵能 | 二游 42 角色 |
| 2 | 议题本身是**比较/排序/谁更/排行**，且主体 ≥3 | 排序需要**统一口径**，否则换个人重跑结论相反 | 角色分析·排序键差 20 倍 |
| 3 | 词族里 **≥2 族命中封顶**（`capped=true`，即 1000） | 广扫已经饱和，再加词只会更饱和——只能换测量单位 | 二游 8 族全封顶 |
| 4 | 该议题**库里已有 ≥1 轮**，且 `gaps` 里有结构性缺口 | 第二轮的边际价值取决于"上一轮缺的是结构还是样本" | 二游三轮 |
| 5 | 用户措辞含「**全面 / 所有 / 逐个 / 每一个 / 彻底**」 | 用户明确要覆盖度，不是要结论 | — |
| 6 | 议题涉及**时间跨度**（"这几年怎么变的"） | 需要按年份分段扫，成本天然翻倍 | 汽车/短剧议题 |

否则 **L2**；用户说了「简要/快速/简单了解」→ **L1**。

> **不要反问"要多深"**。判档是流程的事，不是用户的事——用户已经用措辞回答了。

## 四、中途升降档（跑起来才发现）

### 4.1 升级触发（L2 → L3，命中任一）

| 信号 | 阈值 | 说明 |
|---|---|---|
| 样本不足 | L1 初筛后剩 **< 8 条** | 不是"议题冷"，多半是词族打偏；先补词族，再补矩阵 |
| 结论不收敛 | 冲突 **≥5 条**且互不否定 | 需要一根新轴（换人群/换时间/换主体）来裁决 |
| 证据偏弱 | C/D 级占比 **>40%** | 需要补做轮：换视频、换样本类型 |
| 评论区结构性异常 | 当事账号/官方号/机构号占高赞 | 评论区不再代表受众，必须换样本池 |

### 4.2 止损（任何一档都要守）

| 条件 | 动作 |
|---|---|
| 连续 **3 条**新证据不改变任何结论 | 收敛，进阶段 3 |
| 上游请求 **> 档位上限 ×1.5** | 停，写进 §五「预算与实际」 |
| 单轮 **> 45 分钟** | 停，未覆盖方向写进缺口 |
| 同一动作重复 **2 次**仍失败（接口返回空/风控） | 换样本，不重试第三次 |

### 4.3 🔴 铁律：每次升级必须新增一根轴

允许的轴：**测量单位**（视频→角色/产品）、**样本池**（评论区→画像/官方稿）、
**时间切片**（全量→按年）、**反证方向**（同议题→跨事件）。

不允许的"升级"：同义词再搜一轮、同一条视频再读一遍、把 9 条深挖加到 20 条但仍是同一批词族。
**那不是加力度，那是加引文。**

## 五、L3 的矩阵测量协议

当一个议题的主体多到"抽样讲不清"，就把它变成一张可复现的表。

### 5.1 六个步骤

1. **定主体清单**（N 个），来源必须写清：官方名单 / 榜单单页 / 社区提名 / 上一轮遗留。
2. **一个主体一次检索**：`search_videos(keyword="<主体名> <限定词>", order="click", page_size=50)`。
   —— 注意这是 `order=click`（按播放）而不是默认排序，**排序键必须写进报告**。
3. **指标 ≤4 个**，且都能从返回里直接算：二创 Top10 播放和（剔除官方号）/ 官方最高播 / 评论和 / 发布中位月龄。
4. **别名与异体字回检**：同一主体的不同写法会差 3–4.8 倍（耀嘉音 1982 万 vs 耀佳音 655 万）。
   批量测量前先跑一遍写法对照，**否则你测的是写法差异，不是人气差异**。
5. **共用标记**：一条爆款可能同时是多个主体的 Top1（斯卡蒂与凯尔希共用 4042 万）。
   表里必须有「共用」列，**不重复计入独占**。
6. **只给序关系，不给绝对值**：封顶 1000 时"播放量"只能当排序用，不能当"这个话题有 X 条内容"。

### 5.2 画像派单（L3 的第二种样本池）

- 按主体**分组**派单（一组 2–4 个主体），不要一条视频一个子代理——那样只能拿到"视频说了什么"。
- 每组读 1–2 条**有社区判断**的视频评论（优先高播放二创的评论区，人群代表性最好）。
- 单份画像 **≤1,400 token**，结构固定：`量级｜偏好类型｜怪信号｜缺口位置｜证据强度`。
- **另设怪信号专组**：抽象/黑称/高反差 一组，下头/发癫/性化 一组。
  正常派单的画像会系统性过滤掉这些，而它们往往是最有解释力的部分。

### 5.3 补做轮（L3 必须有）

评论接口会对部分稿件返回空（`reply_total=null`）——**这不等于"没人讨论"**。
补做的正确做法不是重试同一条，而是**换载体**：
角色曲 / 官方叙事 / 人物志 / 攻略 的评论区，一次就能取到（实测 5 个角色全部补齐）。

## 六、账要记在协议里

阶段 0 落协议时，`budget` 里必须带档位；中途升级要留痕：

```json
"budget": {
  "tier": "L2",
  "tier_history": [{"from": "L2", "to": "L3", "at": "阶段1",
                    "trigger": "初筛后仅剩 6 条", "new_axis": "角色级矩阵"}],
  "深挖条数": 12, "扫描次数": 6, "探针次数": 2
}
```

> ⚠️ 不要写 `"调用上限": N`——那个口径已废弃（一次 `scan_topic` 按关键词数打上游，
> 写 30 一开局就超支）。计量只用：**扫描次数 / 深挖条数 / 探针次数**。

报告 **§五 必须写三行**：本轮档位、有没有升级（触发是什么、新增哪根轴）、实际 vs 基准。
**不写就等于让读者以为这就是这个议题的全部深度。**

## 七、发车前的自检

- [ ] 档位判过了，且理由能一句话说清（"主体 42 个，抽样讲不清"）
- [ ] 若 L3：主体清单有来源、排序键写进报告、别名回检做了、共用列有了
- [ ] 若中途升级：新增的那根轴写进 §五，不是"多读了几条"
- [ ] 子代理数量与档位匹配（L2 8–12 / L3 15–25），不是"想到几个派几个"
- [ ] 止损线记住了：3 条不改结论 → 停；1.5× 预算 → 停
- [ ] 协议 `budget.tier` 已写，`tier_history` 有升级就记
