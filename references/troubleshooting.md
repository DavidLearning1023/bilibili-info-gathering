## 流程类问题

### Q1：搜不到足够候选（去重后 < 15 条）

**不是故障，是信号。** 先判断是哪种情况：

| 症状 | 含义 | 处理 |
|---|---|---|
| 每组词都只有零星结果 | **议题太窄**，B站上确实少 | 如实告诉用户"B站上关于这个议题的内容很少"，并给出建议的替代渠道 |
| 多组词结果高度重叠 | **关键词族不够分散** | 补 ④ 黑话类和 ② 上位词 |
| 结果很多但都评到 3/4 | **议题的措辞和B站的实际说法不匹配** | 重新做阶段 0，换用户视角的说法 |

> ⚠️ **不要为了凑数量而降低纳入标准。** 候选少本身就是结论的一部分。

### Q2：搜出来全是带货 / 营销内容

说明这个议题**在B站已被商业化**（常见于工具、课程、数码类）。

**处理**：
1. 加"避坑""翻车""退款""退款难"等**负面词**再搜一轮
2. 改用"×"类词：`X 替代`、`X 平替`、`不用 X`
3. 在简报的「缺口」里写明：**该议题在B站的内容生态已被营销内容占据**

### Q3：候选很多，但读完发现全是复述

**这是B站最常见的情况**（搬运/二创生态导致）。

**处理**：
1. 不要慌——**这本身就是重要发现**，写进简报：「N 条候选中 X 条为冗余源，原创源仅 Y 条」
2. 集中火力在原创源和冲突源上
3. 如果一条原创源都没有 → 说明该议题的一手信息不在这里，**转外部渠道**

### Q4：无法判断来源等级

典型情形：UP 主没有简介、没有其他内容、视频内容也看不出出处。

**处理**：
- **评 F**（无法判断来源），不要勉强评 C
- 但**可用度照常评**——F1 是有效组合，仍然要深挖
- 在简报里明确写「来源无法判断」

> **F 不是差评，是"没有依据"。** 把没依据的评成 C，等于造假。

### Q5：两个来源严重冲突，无法判断谁对

**这正是简报「冲突与未收敛处」存在的意义。** 不要强行裁决。

**处理**：
1. 先查**是不是基准不同**（最常见）——同一个数字，拿一线城市比和拿二三线比，结论相反
2. 若基准相同仍冲突 → 追到一手（找官方文档/原始数据）
3. 追不到 → **两边都列**，写清各自的依据强度

> 记住：**你不需要给用户一个答案，你需要给用户"这个问题上有哪些说法，各自站不站得住"。**

### Q6：预算用尽但感觉没搜完

**正常。** B站可搜索空间是无穷的，**REA 之所以叫"Rapid"，靠的就是一开始就接受"不穷尽"**。

**处理**：进入阶段 3，并在简报里写「本次覆盖 N 条；未覆盖的可能方向是……」

> ⚠️ **不许把"本次未覆盖"写成"没有"。** 这两句话在读者眼里是完全不同的结论。

### Q7：`registry.py` 报 JSON 解析失败

**不要直接删文件**——那是累积的资产。

```bash
# 先看哪里坏了
python -c "import json;json.load(open(r'<路径>',encoding='utf-8'))"
```

修不好时：把坏文件重命名备份（`sources.json.bak-<日期>`），再跑 `registry.py init` 重建空库。
**下次别再手写 JSON** —— 一律用 `registry.py` 的 `upsert-*`。

### Q8：同一个视频被分析了两次

说明 `videos.json` 没起作用。检查：
1. 任务开始时**有没有先跑 `registry.py get-video --bvid ...`**
2. 任务结束后**有没有 `upsert-video`**

> 这两个动作是"资产积累型"的定义性行为，漏掉就等于退化成"用完即弃"。

## 与精读 skill 的边界问题

### Q9：用户既给了 BV 号，又提了一个议题

**处理**：先用本 skill 广扫定位（那条 BV 是否是最值得看的），再对那条走精读 skill。
**不要**在本 skill 里重写一遍精读逻辑——那会让两套方法论分叉。

### Q10：有些内容本 skill 也需要精读级的方法论

比如阶段 2 要判断 AI 字幕误转、要区分三源。

**处理**：**引用，不复制。** 指向姊妹 skill `bilibili-video-analysis-summary`
的 `references/` 目录（在你的 skills 目录里按这个名字找）。
改动共用部分时，**先改精读 skill，再检查本 skill 是否需要同步**。
