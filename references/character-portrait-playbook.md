# 角色画像采集与判读（playbook）

> 适用：议题是「某社区如何看待某个角色/人物」，而不是「这个角色怎么玩」。
> 来源：2026-10 二游超人气角色议题（39 个角色、6 款游戏、15 个子代理）的实地经验。
> 定位：**描述性经验**，不替代 `source-grading.md` / `opinion-distribution.md` 的判据；与判据冲突时以判据为准。

---

## 0. 一句话

**画像不是人设摘要，是社区给角色分配的「关系位」＋一个「降格动作」＋一个被反复消费的「缺口」。**

- 关系位：女儿、老婆、妈、师父、上司、爷、容器、他者。
- 降格动作：黑称、地狱笑话、性化、亲属化、抽象化。
- 缺口：身份（神→人）、命运（生→死）、身体（完整→可观看）、关系（我→她）、文本（说→没说）、设定（有→无）。

三者缺一，画像不成立：只有关系位是官方设定，只有降格动作是梗，只有缺口是同情。

---

## 1. 什么时候用

| 适用 | 不适用 |
|---|---|
| 角色人气 / 魅力 / 社区偏好 | 纯强度、抽取建议、配队攻略 |
| 粉黑大战 / 争议 / 口碑 | 单条二创作品赏析（无社区判断） |
| 二创生态 / 梗传播 / 同人文化 | 官方 PV 的画面分析（除非要看评论区） |
| 「为什么这个角色火」/「为什么过气」 | 角色数值/机制拆解 |

---

## 2. 先做量级，再做画像

不要一上来就派子代理读评论。先用一次脚本把「谁值得做画像」定下来。

**检索式**：`角色名 + 游戏名` → B站搜索 `order=click` → `page_size=50` → 剔除官方账号 → 二创 Top10 播放和。

**同时记录**：

| 指标 | 用途 |
|---|---|
| 二创 Top10 播放和 | 量级基线（只给序关系，不是统计值） |
| 官方最高播 | 官方投入 |
| 官方 ÷ 二创 | 判断引擎：双引擎 / 生态 / 供给 / 双低 |
| 评论和 | 讨论热度 |
| 发布中位月龄 | 新角色还是存量 |
| 共用 BV | 防止把一条爆款算给多个角色 |

**关键**：量级只决定「先做谁」，不决定「谁更火」。真正的人气要拆成三轴：认知（多少人知道）、关系（多少人认领）、转化（多少人付费/入坑）。播放量只测认知。

---

## 3. 选样：哪种视频的评论区能出画像

优先级从高到低：

1. **高播放二创 / 整活**：评论区是社区自己的语言，黑称、梗、下头都在这里。
2. **人物志 / 「为什么是 ta」**：有论证，能拿到「魅力拆解」的框架。
3. **争议 / 黑称 / 下头视频**：能拿到边界与反方。
4. **官方 PV**：只看评论区有没有被梗入侵（例如官方非角色 PV 下出现角色梗），不看本体。

**不要用**：攻略、抽取建议、剧情合集、纯 MMD（除非评论区有判断）。

**标题反讽识别**（本轮踩过的坑）：

- 「这是终末地最聪明的干员」→ 全片在拍她傻，标题是捧杀。
- 「Logos 为什么是方舟顶流」→ 标题是 UP 定性，评论区才有「六要素」共识。
- 「不能天使」→ 强度负面命名，不是角色名。

看到标题带「最」「顶流」「神」时，先假设它是修辞，去评论区找反证。

---

## 4. 读评论：40–60 条顶层就够

- 用 `deep_read(channels=["comments"], comment_n=40~60, comment_detail="opinion")`。
- **只读顶层**，楼中楼只在需要引用原话或读争论时开 `full`。
- 记录每条：赞数、楼层、是否有图、作者等级。
- **区分三类赞**：
  - 图赞（纯图/表情）：表态，不含论点；
  - 梗赞（复读/接龙）：使用即认同，但不提供理由；
  - 论证赞（长评/考据）：信息密度最高。
- 高赞 ≠ 共识；正反都要记；被骂得多也可能是顶流。

**引用纪律**：单条 ≤35 字，必须带赞数/楼层；露骨内容只做类型归纳，不引原句。

---

## 5. 画像卡：六个字段

每个角色一块，固定六项：

| 字段 | 写什么 | 反例 |
|---|---|---|
| **社区身份** | 社区自己的说法，不是官方介绍 | 「蒙德最强战力」（官方） |
| **核心标签** | 3–5 个，含爱称/黑称，带赞数 | 「可爱、元气」（无证据） |
| **证据** | 1–2 条原话，带赞/楼 | 「评论区都在夸」 |
| **怪信号** | 下头/抽象/地狱笑话/性化/高反差，**说明它代表什么** | 「有下头评论」（不解释） |
| **最强魅力层** | 外观 / 关系 / 叙事 / 二创适配，哪层最强＋一句为什么 | 「都强」 |
| **反面** | 最有力的不喜欢/争议，带赞 | 「没有反面」（通常是没读到） |

**好画像的三个标准**：有称呼（社区怎么叫）、有降格（被玩成什么）、有反面（谁不喜欢）。

---

## 6. 怪信号六类与六条判据

| 类型 | 实际语义 | 例子 |
|---|---|---|
| **自取黑称** | 抢先命名＝抢回定义权，贬词被改造成会员证 | 阿驴 451；牢猫 2612；鲨鱼妹 7985 |
| **地狱笑话** | 哀悼的公共形式：把无法承受的重量变成可共同分担的东西 | 白厄「跑得快死得快」4736 |
| **抽象极简** | 我在、我懂，但拒绝给可被反驳的论点 | 「依旧」10107；纯图 1586 |
| **下头/发癫** | 可撤回的告白（deniable confession） | 献心脏 19227；当狗 309 |
| **高反差二创** | 祛魅：把完美角色拉回可以戏弄的距离 | 管理员县城老干部 18.3 万赞 |
| **亲属化/倒错** | 用家庭词改写权力/年龄/亲密关系 | 洛茜妈妈；凯尔希「妈系」1970 |

**六条判据**：

1. 看主语：「我们/我推/你绝姐」＝自己人；「他们/那帮」＝真黑。
2. 看同场词：「厨/推/抽/二创」＝爱称；「退游/删号/流水/恶心」＝攻击。
3. 看是否自带解释：自己人会叠甲；真黑不需要翻译。
4. 看反驳方向：高赞零反驳＝共识；个位数赞＋回复＝边界争议。
5. 看能否被收编：已成表情包/小曲/头像＝收编；只活在攻击视频弹幕＝未收编。
6. 看露骨度与赞数：**负相关**——最露骨 1–13 赞，包装过的 453/460 赞。

**一条边界**：社区真正反感的不是「性化」，是「降维」——把复杂人物读成「约会/老婆」会被斥「没看懂、重修语文」71 赞。硬边界由平台审核划，不由社区划。

**用途限制**：怪信号可以当画像证据，不能当好感证据；它测的是「可消费性」，不是「人气」。

## 7. 关系位的三种来源、缺口的两种来源

**关系位**：

| 来源 | 机制 | 例子 | 稳定性 |
|---|---|---|---|
| 官方明示 | 剧情/语音直接写 | 爱弥斯「女鹅」、守岸人「等你」 | 高 |
| 官方暗示—社区认领 | 官方留白，社区命名并传播 | 凯尔希「妈系」、芙宁娜「傻芙」 | 中高 |
| 社区先入为主（OOC） | 第一印象压过设定，社区自造 | 洛茜「妈妈」、庄方宜「恋爱线」 | 低，易与玩家实感冲突 |

**缺口**：

| 来源 | 机制 | 例子 | 后果 |
|---|---|---|---|
| 设计留白 | 官方故意不写满 | 管理员无脸、开拓者无固定人设 | 稳定 |
| 过度理解 | 社区把小特征放大成画像 | 陈千语「傻子」、洛茜「妈妈」 | 传播快，但官方补设定就可能塌 |

> 写报告时不要把所有缺口都归给制作组。**过度理解必须有一个可被反证的原点**；没有原点的，只是误读。

## 8. 十个陷阱（按代价排序）

1. **排序键**：`order=click` vs 综合，同一角色同一时刻能差 20 倍。先声明排序键。
2. **把「搜索没看到」当「不存在」**：相关性排序会把高播放旧二创压下去。
3. **写法/别名**：耀嘉音 1982 万 vs 耀佳音 655 万；卡提希娅 3829 万 vs 卡缇希娅 812 万。
4. **共用爆款**：斯卡蒂/凯尔希共用 4042 万；小企鹅/管理员/陈千语/佩丽卡/庄方宜高度重叠。
5. **群像/机构号**：群像曲会让多个角色同时上榜；最高赞可能来自官方号。
6. **标题当结论**：UP 的「顶流/最聪明/不能天使」都是修辞。
7. **图赞当认同**：千夏 89.6% 赞在图上；塔露拉 70.3% 是纯表情。
8. **OOC 关系位当官方**：社区自造的「妈妈/恋爱线」不是设定。
9. **过度理解当设定**：社区放大出来的「傻子」可能档案里是「过目不忘」。
10. **新角色过早下结论**：祀上线 11 天，只能写「先成梗、后成角色」。

## 9. 并行与成本

- 按**游戏**分组，不按角色分组：同一游戏的社区语言共享，一个子代理能读 3–6 个角色。
- 每个角色 1–2 条视频；每条 40–60 条顶层评论。
- 子代理回传 ≤1200–1400 token/组；主上下文不读原始评论。
- 给每个角色准备**备用 BV**：评论接口会对老稿/部分稿件返回空（`reply_total=null`），换稿比同稿重试有效。
- 先做 2 次探针验证词族，再决定是否广扫。

## 10. 交付前检查清单

- [ ] 每个角色都有评级（A2/B2/C1/D2），降级有原因。
- [ ] 每个角色都有至少一个称呼/黑称，或明确写「无明显黑称」。
- [ ] 每个角色都有反面，或明确写「样本内无反声」。
- [ ] 引用都带赞数/楼层，单条 ≤35 字。
- [ ] 矩阵里标了「共用」与「单视频」。
- [ ] 社区偏好能压成一张「缺口位置表」。
- [ ] 冲突不裁决，写清 A/B 两方与「未收敛/基准不同」。
- [ ] 偏差声明写了排序键、写法、共用、图赞、接口降级。
- [ ] 方法能被另一个人复现（检索式、样本量、时间窗口）。
