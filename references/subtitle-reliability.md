# 字幕可靠性

> 方法论来源：姊妹 skill `bilibili-video-analysis-summary` 第 3 步。
> **引用，不复制**——本文件只做「议题级场景下需要什么」的裁剪。

> 适用：阶段 2 深挖字幕时。**字幕是最容易把错误带进结论的通道**——
> 术语错一个，后面所有推论都建立在错的前提上。

---

## 一、三种字幕，区别对待

`get_transcript` 返回 `data_source` 字段，**必须区别对待**：

| data_source | 含义 | 处理方式 |
|---|---|---|
| `subtitle` | UP 主上传的人工字幕 | **可直接引用** |
| `ai_subtitle` | **B站机器转写，可能有错** | 数字/术语/人名**一律标注"建议回原片核对"** |
| `asr` | 本地 ASR 自建转写（本项目 `transcribe_audio`） | 同上，且**要注明转写模型**（返回里的 `engine` 字段） |

> `ai_subtitle` 与 `asr` 的处理标准**完全一致**。本地转写并不会更准。

---

## 二、⚠️ 判「有无字幕」必须带登录态

未登录时 B站 `player/v2` 返回**空字幕列表**，**看起来像"没字幕"**。

实测校准：搜索"离散数学"的 6 个视频 + 作者官方验收示例（195 个分P）
在**未登录时全部返回空字幕列表**。

> **空列表不能作为"没字幕"的证据。**
> 本项目的 `get_transcript` 用了登录态取（`load_cookie()`），
> 但你若自己另写取数逻辑，**必须带 cookie**。

判据顺序：
1. `data_source` 存在 → 有字幕（可能是 AI 字幕）
2. 传了 cookie 但仍返回空 → **真的没字幕** → 走第三节的 ASR 通道
3. 压根没传 cookie → **不知道**，别下结论

---

## 三、没有字幕时：本地 ASR 自建转写

新发的视频常常既无 CC 也无 AI 字幕。**这时候只有两条路**：本地 ASR，或抽帧。

```python
transcribe_audio(bvid="BVxxx")
```

它做三件事：下载音轨 → 调本地转写后端 → 输出**与B站字幕同构**的 transcript
（`data_source="asr"`，带 `from`/`to`/`content`），可直接接进后续流程。

### 后端怎么找（**先复用已有工具，不要重复安装**）

后端优先级：

| 优先级 | 后端 | 说明 |
|---|---|---|
| ① | `BIG_ASR_CMD` | 用户显式指定的命令（最高优先级） |
| ② | **共享 ASR 运行时** | 独立 venv + `asr_transcribe.py`，装在 `BIG_ASR_HOME` 或约定位置（`~/.local/asr` 等）。**多个项目共用一份**，脱离任何产品的受管目录，版本可锁 |
| ③ | **`local-audio-transcription` skill** | **本机已装**。它的 `transcribe.py` **已内置三个坑的修复**，比自己写一遍可靠得多 |
| ④ | 当前解释器里的 `faster_whisper` | 装在**本项目 venv** 里时可用 |

> ⚠️ **装在别的 venv 里 ≠ 装在本项目里。**
> 很多机器上 faster-whisper 装在**受管 venv**（如 `~/.workbuddy/binaries/python/envs/*/`），
> 本项目的 `.venv` 里 `import faster_whisper` **会失败**。
> **这种情况不是"没装"，是"装在别处"**——工具会自动去找并直接调用它，
> **不要重复安装**。

本项目会自动在 `~/.workbuddy/skills/`、`~/.minimax/skills/`、`~/.claude/skills/`
下找 `local-audio-transcription`，并挑选**真正能用 GPU** 的那个受管解释器。

> ⚠️ **选解释器不能只看"存在"或"装了 faster_whisper"。**
> 实测：受管 envs 里的 `asr` 装了 faster-whisper 但**没装 nvidia CUDA 运行库**，
> 选中它会在跑到一半时炸 `Library cublas64_12.dll is not found or cannot be loaded`——
> 错误信息完全指不到"你选错了解释器"。
> 正确判据：**把 nvidia bin 目录前置进 PATH 后，ctranslate2 能看到几张卡。**

> ⚠️ **共享运行时的判据是"三信号齐"，不是"目录存在"。**
> 解释器 + 入口脚本 `asr_transcribe.py` + site-packages 里**真的**有 `faster_whisper`，
> 缺一不认。否则"目录建了但没装包"的半成品会在真正转写时才炸。

> ⚠️ **装运行时务必锁 `av<19`**（2026-10-21 实测）。
> PyAV 19 移除了 `av.open()` 的 `metadata_errors` 参数，而 faster-whisper 1.2.1
> 的 `audio.py` 仍在传它 → `TypeError: open() got an unexpected keyword argument
> 'metadata_errors'` → 整条转写链路全废。
> **而且是运行时才炸**：装包、import、模型加载、GPU 识别全都正常，
> 只有真正解码音频时才报错，错误信息还完全指不到真因。

### 实测基线（本机）

| 项 | 值 |
|---|---|
| 后端 | **共享 ASR 运行时**（`~/.local/asr`，独立 venv，与 WorkBuddy 无关） |
| 解释器 | `~/.local/asr/Scripts/python.exe`（base = `miniconda3`，Python 3.14.6） |
| 模型 | `large-v3-turbo`（HF 缓存已有，**不重复下载**） |
| 精度 | `cuda / float16`（Blackwell 上必须显式，`auto` 会炸 `CUBLAS_STATUS_NOT_SUPPORTED`） |
| 速度 | **78 倍实时**（1824 秒音频 → 23.4 秒出稿） |
| 体积 | 1,191 MB（其中 nvidia/cublas 736 MB 不可省；**cuDNN 1,092 MB 实测不需要**） |
| 输出 | `<outdir>/<stem>.json` + `.srt`，本工具优先读 JSON（时间戳更准） |

> 💡 **cuDNN 不用装**：实测只把 `nvidia/cublas/bin` 前置进 PATH（不暴露 cudnn），
> ctranslate2 照样 `get_cuda_device_count() == 1` 并跑完整个前向。
> 原因是 ctranslate2 自带 0.3 MB 的 `cudnn64_9.dll` 转发桩，faster-whisper 用不到 cuDNN 的重引擎。

### 没有后端时

工具返回 `status="no_backend"` + 完整安装指引，
并明确告诉你：**把「该视频无可用字幕」记进结论的缺口声明，不要当成「视频没讲」**。

> 这不是可接受的失败——**静默失败会让 Agent 以为"这视频没讲"，直接下错结论**。
> 缺口必须显式声明。

### 实测坑（外部脚本路径已内置，in-process 路径要自己处理）

- **不要关 VAD**（等价于 `vad_filter=False`）：会直接抛
  `RuntimeError: No clip timestamps found`。开着 VAD 时会把整段口播并成
  30 秒级巨块——**粗粒度时间戳够用**，细锚点交给抽帧。
- **CUDA DLL 找不到** → 必须把 `site-packages/nvidia/*/bin` **前置**进
  `os.environ["PATH"]`，且必须在 import ctranslate2 之前执行。
  ⚠️ `os.add_dll_directory()` **无效**（实测过）。
- **Blackwell（RTX 50 系）** 上 `compute_type="auto"` 会选 `int8_float16`
  → `CUBLAS_STATUS_NOT_SUPPORTED`。必须显式写 `float16`。
- **长音频要用 `BatchedInferencePipeline`**：普通 `transcribe()` 只有 2.6–4 倍实时，
  批处理是它的 **~10 倍**。
- 时间戳来自音频本身，与视频时间轴一致，可直接构造 `?t=秒数` 跳转链接。

> 💡 **本地 ASR 一样会误转。** 实测本机转写把「宽**基**ETF」转成「宽**机**ETF」、
> 「**极**其爆发」转成「**及**爆发」——所以下面的第四节对 `asr` 同样适用。

## 四、AI 字幕的常见错误模式（主动排查）

技术类视频里，这几类是高频的。**通读时主动找**，找到就是"校验型发现"：

| 模式 | 实测案例 |
|---|---|
| **同音/近音词整体替换，且会把语义读反** | 「长上下文」→「**常识**」；`prefill` → `prefer` |
| **数字失真** | `256K` → `250K` |
| **专有名词/参数名损坏** | `27B` → `27P`；`kv_mem_budget` → `KBMMABUDGET` |
| **工具名错** | `WSL` → `WCR` |
| **人名错** | 同音不同字，中文视频尤其常见 |

> ⚠️ **同音词替换可能把语义读反**——这类最危险，因为它读起来通顺。
> 「长上下文」→「常识」在讨论技术的视频里几乎不会引起怀疑。

## 五、⚠️ 说话人分离缺失（比词错更致命）

AI 字幕**没有说话人分离**。多人对谈 / 采访类视频里，字幕是一条流水线，
**你无法从文本本身判断某句话是谁说的**。

实测案例（采访类视频）：字幕出现
「1997 年的时候我大概才十几岁，我爸带我去看海尔-波普彗星」，
单看文字极易误读成受访者自述——但受访者 1963 年生（当年 34 岁），
采访者 1984 年生（当年 13 岁），且下文紧接「但是您看到了」证明叙述者在此转向对方。
**结论：这段是采访者自述。**

### 处理办法：三方交叉反推

遇到「时间/年龄/身份对不上」的叙述，**别急着当误转**，用这三方交叉：

1. **年龄 / 生平**（受访者的出生年 vs 叙述里的年份）
2. **上下文称谓**（「您」vs「你」——谁在对谁说话）
3. **上下文衔接**（下文是否紧接"转向对方"的措辞）

反推出来的说话人归属，要**单列**在结论里。

> **归属错了，观点就安在错误的人头上，比错一个字严重得多。**

## 六、⚠️ 反向核实：术语不规范 ≠ 转写错误

找错字时有个反向陷阱：**受访者本人可能就在用非标准术语**。

实测案例：字幕写「大数据学派」，学术通行命名应是「连接主义」。
若直接列入误转清单，就"纠正"错了——查证后发现该受访者在 2025 年另一场公开对谈中
**本人就用"大数据"指代这条技术路线**，字幕忠实记录了原话。

> **动作**：凡准备把某个术语列入误转清单前，**先搜一下"受访者/作者 + 该术语"**。
> 若对方本人就这么说，要**明确写"这不是字幕错，是受访者的原话"**。

这类反向核实和找到错字**同等值钱**——而且别人几乎不会做。

## 七、数字以画面为准，不以逐字稿为准

> 这条让结论的可靠性高于字幕。多数人默认反着来。

但**不要默认全抽帧**。抽帧是**段级决策**：

| | 该做 | 不该做 |
|---|---|---|
| 触发 | 字幕里出现数字 / 专有名词 / 参数名，且**这个错会改变结论** | "可能读错"、"想更全面" |
| 动作 | 抽**该时间点附近**的一张画面 | 全片抽帧、逐镜头检测 |
| 产出 | 一张图 + 编号 | 几十上百张图 |

```python
grab_frames(bvid="BVxxx", at_seconds=[30.0, 120.0], quality=720)
```

**清晰度**：720 看画面结构够用；**要读表格/榜单里的数字必须 1080**
（实测 640×360 只能认出「正确率」三个大字，格子里全是糊的）。

> 工具自带**定位自检**：若多个时间点抽出的图**完全相同**，说明定位失败
> （一直在读第 0 帧），而 ffmpeg **不会报错**。这种帧不要用。

**要画面但只是想知道"讲了什么"** → 用 ASR，不要用抽帧（抽帧没有文字流）。

## 八、结论里怎么写

发现一条不可靠的字幕，**不要只说"字幕可能不准"**——那等于没说。
按下面三档写清楚：

| 情况 | 怎么写 |
|---|---|
| 术语可能错，但**不影响结论** | 一句话带过，标 `（AI 字幕，建议回原片核对）` |
| 数字可能错，**结论依赖它** | 进「发现」表，但**明确标注"数字待核"**，并说明有没有抽帧核对过 |
| 抽帧核对过 | 正常引用，注明「已按 <时间点> 画面核对」 |

> 没核对过又说不出更细的，就是「数字待核」——**不要装确定**。
