# 双轴分级卡（来源 × 可用度）

> 阶段 1 的核心工具。对每条候选视频给出 `来源等级 + 可用度`，加上一个冗余度标记。
> 依据：Admiralty / NATO 情报评级体系（来源可靠性 A–F × 信息可信度 1–6），按B站场景改造。

---

## 一、为什么必须是两个轴

Admiralty 体系最精妙的地方，是**来源可靠性和信息可信度必须独立评估**。原文反复强调：

> 「一个历史上可靠的来源（A）可能传递了不准确的信息（比如收到二手信息或被骗），得到 **A4 或 A5**；
> 反过来，一个可靠性未知的新来源（F）可能提供了被其他情报证实的信息，得到 **F1**。」

**为什么这对B站特别重要**：B站的信源质量分布极散——有官方机构号、有领域研究者、有搬运号、有纯情绪输出。**用单一"好/坏"排序会丢掉关键信息**：

| 情形 | 单轴评分 | 双轴评分 |
|---|---|---|
| 大 UP 主讲了他不熟悉的领域 | 中 | **A4**（来源可靠，但这条内容可疑） |
| 无名用户贴出政府统计原文 | 中 | **F1**（来源未知，但内容已证实） |
| 官方机构号的宣传稿 | 高 | **A3**（来源可靠，但不是你要的信息） |

后两种在单轴下无法区分，在双轴下**处理方式完全不同**。

## 二、来源轴（A–F）："这个信源值不值得信"

| 码 | 名称 | **B站的判定依据** |
|---|---|---|
| **A** | 一手 / 权威 | ① 作者本人是当事人（当事人自述、亲历者）② 官方机构号 ③ 发布者附了**可核实的一手材料**（原始公告、论文、官方文档、源码仓库） |
| **B** | 专业二手 | 领域从业者或研究者；**有方法论、有引用、有可复现的实测数据**；能看出"他知道自己不知道什么" |
| **C** | 一般二手 | 普通科普 / 搬运 / 二创；信息源自他人且**未标注出处**；内容正确但看不出原创性 |
| **D** | 观点型 | **无数据支撑**的个人主张、情绪输出、带货导向；标题夸张；用"我觉得"代替依据 |
| **F** | 无法判断 | 信息不足：新号无简介、内容与标题不符、无法定位作者身份 |

### 判定时优先看什么（按信号强度排序）

1. **有没有可核实的一手材料**——贴了原始链接/截图/数据表 vs 只说"据说"
2. **有没有方法**——"我测了 A/B/C 三种方案，条件如下" vs "我用过，感觉 X 好"
3. **UP 主在这个领域的持续输出**——用 `get_creator_content(mid, section="videos")` 看：**同一个人在同一议题上发过几条**（系统性输出 vs 蹭热点）
4. **简介里的利益关系**——有没有挂购买链接、推广码、社群入口

### ⚠️ 两个常见误判

- **粉丝多 ≠ 来源可靠**。大 UP 跨领域发言是 A4 的典型来源，不是 A1。
- **官方号 ≠ 对本议题有用**。官方号发的是宣传材料时，它是 A3 甚至 A4，不是 A1。

## 三、可用度轴（1–4）："这条对本议题有没有用"

| 码 | 名称 | 判定依据 |
|---|---|---|
| **1** | **直接可用** | 含本议题需要的关键数据 / 事实 / 结论，**且可溯源**（有出处、有实测条件、有时间戳） |
| **2** | **可参考** | 有相关分析或实测，需要交叉验证后才能用 |
| **3** | **仅背景** | 只有间接相关；或只是复述别人已经说过的东西 |
| **4** | **无关 / 标题党** | 标题相关但内容不相关；或纯营销 |

### 判定的操作顺序

```
先问：它回答了阶段 0 里的哪个核心问题？
  答不上来 → 3 或 4
  答得上 → 再问：它给的是"事实"还是"看法"？
    事实 + 可溯源 → 1
    看法 + 有方法 → 2
    看法 + 无方法 → 3（哪怕说得对）
```

> **注意**：可用度**不是**质量评分。"一条质量很高但和你的议题无关的视频" = A4。
> 可用度永远**相对于本议题**。

## 四、组合编码与处理方式

| 编码 | 含义 | 处理 |
|---|---|---|
| **A1** | 一手且直接可用 | 🔴 **必进阶段 2**，且作为交叉验证的基准 |
| **B1** | 专业且有可溯源数据 | 🔴 **必进阶段 2** |
| **A2 / B2** | 专业且有分析 | 🟡 视冗余度决定（原创源进，冗余源不进） |
| **F1** | 来源不明但内容已证实 | 🔴 **必进阶段 2**——去查它引用的是什么，往往能挖到真一手 |
| **C1** | 搬运但内容可溯源 | 🟡 顺藤摸瓜找原出处，找到就降级为背景 |
| **A3 / B3** | 专业但只沾边 | ⚪ 留作背景，不进阶段 2 |
| **C3 / D2 / D3** | 无原创性的二手 / 无依据的观点 | ⚫ 淘汰（除非它是唯一的冲突源） |
| **D4 / 任何 4** | 无关 | ⚫ 淘汰 |

**冲突源例外**：任何标记为「冲突源」的条目，**无论评级如何都要看一眼**——因为"哪里对不上"往往比"哪里都对得上"更有价值。（但若它是 D4，可以只看它的主张是什么，不必细读）

## 五、冗余度标记（第三个维度，B站特有）

B站的搬运 / 二创生态导致**互相复述的内容远多于论文库**。所以除双轴外，再加一个标记：

| 标记 | 定义 | 为什么重要 |
|---|---|---|
| **原创源** | 提供了别处没有的信息（独家数据、亲身经历、原创方法） | 证据强度最高 |
| **冗余源** | 只是复述已知内容，无信息增量 | **"10 条互相复述"和"1 条独家 + 9 条复述"是完全不同的证据强度**，但粗看数量一样 |
| **冲突源** | 与已知内容矛盾 | **必须深挖** |

**判定时机**：
- 阶段 1 结束时给出**初步标记**（基于元数据 + 前 15 条评论）
- 阶段 2 读完字幕后**修正**（很多"看着像原创"的其实是复述）

> ⚠️ **不标冗余度的后果很严重**：用户会误以为"这么多人都在说 = 可信"。
> 这恰恰是信息茧房的形成机制——**同一条信息被搬运十次，看起来就像十个独立来源。**

## 六、辅助信号（不拉字幕时能用）

这些**不能直接定级**，但能作为交叉参考。任何一个信号单独都不足以下结论。

| 信号 | 读数 | 含义 |
|---|---|---|
| **赞／币比** | ≥20:1 | 情绪型倾向（D 类）；1–3:1 → 留存型 |
| **收藏／点赞比** | >50% | 工具型 / 可复用，信息密度可能高 |
| **评论／点赞比** | >10% | 评论区是主战场 → **侧读时要重点翻** |
| **时长** | <2 分钟 | 几乎不含深度信息 |
| | >60 分钟 | 需警惕注水（但技术类长视频可能真有料） |
| **发布日** | 工具类 >18 个月 | 基本失效 |
| **播放量** | 高 | ⚠️ **与可信度无关**，只说明传播度 |

> 🔴 **播放量不是质量信号。** 实测反例：某 83 秒段子 94 万播放，信息价值接近零。
> 用播放量排序搜索结果是算法行为，不是证据排序。

## 七、与信源库的联动

**定级前先查 `sources.json`**：

```
若该 UP 主已有评级：
  → 沿用，标注「沿用历史评级（<日期>），本次未复核」
  → 但若本条的领域与历史领域不同，必须重新判断来源轴（大 UP 跨领域 = A4）
```

**定级后更新 `sources.json`**：
- 新 UP 主入库
- 已有 UP 主：`observations +1`；若与历史评级不一致，**记录不一致本身**（这往往是重要信息：一个靠谱的 UP 突然发了条不靠谱的，或者反过来）

详见 `references/registry.md`。

## 八、⚠️ 一个双轴处理不了的情况：价值全在评论区

**实测案例**：某 83 秒 AI 换脸段子（BV1JHYg6yEPY）。

| 对象 | 评级 | 说明 |
|---|---|---|
| **视频本体** | **D4** | 段子，无岗位/技能/行业信息；涨薪依据只有「你这个学历」 |
| **它的评论区** | **A1** | 该议题上最密集的一手讨论：政府统计处原文、深挖通勤的逐项测算、在港者的反向证词 |

双轴分级卡评的是**视频本体**，所以这条会得到 D4（淘汰）。但把它淘汰掉是**错的**——它的评论区是本议题最有价值的东西。

### 处理规则

**当「阶段 1 的前 15 条评论」显示出与视频本体严重不匹配的信息密度时**（评论里有具体数据、有反驳、有实测），**不要按 D4 淘汰**，而是：

1. 在信源地图里给视频本体照常标 **D4**，但**另起一行标注「评论区：A1」**
2. **进阶段 2**——但深挖的对象是**评论区**，不是视频
3. 在 `videos.json` 的 `verdict` 里写明「视频本体不可用，价值全在评论区」

### 怎么在阶段 1 就发现它

三个信号同时出现时，基本可以确定是这种类型：

```
① 赞／币比 ≥20:1（情绪型内容）     ← 说明视频本体是段子
② 评论数／点赞数 >10%              ← 说明评论区是主战场
③ 前 15 条高赞评论里出现具体数据    ← 说明评论区有真材实料
```

> **这是"侧读"（SIFT 的 Investigate）在B站最典型的应用**：
> **不要相信视频对自己的描述，去看别人怎么评价它。**
> 一条视频的评论区，往往比视频本身更能定性它。

## 特例二：情绪轴（2026-10-19 实跑新增）

上面那个特例是"视频无用、评论区是金矿"。还有一类更隐蔽的：

**视频本体和评论区都没有信息，但整条视频是"当下群体情绪"的一手样本。**

实测样本：《久留美：不要怕！技术性调整！给我加杠杆》——75 秒二创梗视频，
方法价值 0（D4），评论区也全是玩梗。但它：

| 指标 | 数值 | 与方案派视频对比 |
|---|---|---|
| 点赞率（赞/播放） | 12.4% | 方案派约 2.4%，**高 5 倍** |
| 评论/弹幕 | 11.17 : 1 | 方案派约 0.6–1.9 : 1 |
| 高重复句 | `火力加仓王` 21×、`神了` 21× | — |

### 处理规则

当议题是**「大家对 X 的态度」**而不是「X 怎么做」时，这类内容**不能按 D4 淘汰**：

1. 评级写成 **`D4 / 情绪轴 A1`**（方法轴照常给 D4，不美化）
2. 它在信源地图里的角色是「**情绪极值点**」，不是「证据」
3. 只用在「发现」一节的**情绪/共识**部分，**不能用来支撑任何事实主张**

### 一个反直觉的推论

**点赞率与信息量成反比。** 实跑里点赞率最高的（12.4%）是纯梗视频，
点赞率最低的（1.7%）反而是最硬的财经分析。所以：

> **不要用"这条火了"当"这条可信"的证据。** 在 B站，火往往意味着"好消化"，
> 而好消化通常意味着信息密度低。

## 特例三：图片在「态度类」议题里是表情，不是证据

精读 skill 的实战结论是「评论区图片常是一手材料」（统计原文截图、实测照片、逐项测算）。
**在态度/情绪类议题里这条会反过来。**

实测：《存钱=亏钱?》前 100 条顶层评论中 31 条带图、占赞 39.2%（判据 `must`）。
看过联系表后分类：

| 类型 | 占 20 张样本 |
|---|---|
| 情绪梗图 / 自嘲 | 约 8 |
| 收益 / 持仓截图 | 约 6 |
| 真·信息性材料 | 约 6 |

### 规则

**判据（图片占总赞 ≥15%）只回答"该不该看"，不回答"看到的是什么"。**
必须**看完联系表再决定用途**：

- 出现具体数字/截图 → 可作证据，但**只认原图**
- 主要是梗图 → 只能作情绪证据，**不能进「发现」的事实列**

不要因为 `must` 就假设那里有材料。

## 九、同一 BV 二次评级：字母要稳，数字可以变（2026-10-22 实测）

同一议题先跑「深入」、后跑「简要」，两轮都会给同一批视频评级。实测对比
`分析报告库/20261022-*` 两份报告：**14 条可比 BV 里 10 条评级不同，其中 7 条连来源字母都不一样**
（`BV1W6nq6AEm5` 深入 D2 / 简要 C2，`BV1pGnn67EC2` 深入 A2 / 简要 B1）。

这不是"第二次判断更准"，是**没有锚点**：简要模式没读字幕，把"没读到"当成了"来源不可靠"。

### 规则

| 轴 | 能不能因模式而变 | 理由 |
|---|---|---|
| **来源轴（A–F）** | **不能** | 作者是谁、有没有一手材料，与"这轮读没读字幕"无关。没读字幕是**证据缺口**，不是来源降级 |
| **可用度（1–4）** | **可以** | 它相对本议题、也相对本轮证据深度；简要轮没读本体，给低一档是诚实的，但必须在信源地图备注「仅评论侧」 |

### 操作

1. **评级前先查**：`registry_get(kind="video", bvid=...)` 或 `kind="videos"` 看已存 `grade`。
2. **字母一致**：与已存记录一致，除非你在 `grade_basis` 里写明"为什么这个来源本身该改判"。
3. **数字可不同**：但要在信源地图的「一句话定性」里说清证据范围（例："仅评论侧，未读本体"）。
4. **被覆盖会自动拦**：`upsert_video` 在"旧记录读过视频本体、新记录没读、议题相同"时
   **保留旧评级**，把新评级记进 `grade_history` 并标注 `kept:false`；返回里的
   `changes.grade_kept` 会告诉你发生了什么。

> `render_briefing.py --check` 会跨报告比对信源地图的字母评级：同一议题内不一致会出现在提醒里。
