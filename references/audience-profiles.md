# 用户画像与交付适配

> 这份文档回答一个问题：**这个 skill 是给谁做的，因此哪些取舍是对的、哪些是不该妥协的。**
> 写在 2026-10-21 与作者确认之后——在这之前，「普通用户」被误当成
> 「只想三分钟拿到答案的人」，那会导致一批错误的简化建议。

---

## 零、先说不是什么

**本 skill 不服务「三分钟要一个答案」的提问者。**
这类需求用通用搜索就够了，走本流程是**降级**（成本高、结论慢、还要求你先回答意图类型）。

它服务的是：**愿意为一个议题投入 10–20 分钟、并且要拿到「能支撑判断的证据」的人。**
判断标准很简单——**你会不会拿这份产物去跟别人争论，或者写进一份要给第三方看的材料。**
会，就用本 skill；不会，就别用。

---

## 一、用户 A：自用型研究者（当前唯一真实用户）

**画像**：作者本人这一类——有分析训练、懂方法论、能判断信源质量，
但**不愿意手工做三小时的检索与清洗**。要的不是"替我想"，是"替我跑腿 + 别漏"。

| 维度 | 需求 | 本 skill 的应对 |
|---|---|---|
| 目标 | **把议题理解透**，不是"有个答案" | 三阶段漏斗 + 冲突单列 + 缺口二分 |
| 对 AI 的期待 | 判断由强模型做，但**不许黑箱** | 双轴评级、每条事实带来源、clusters 落盘 |
| 时间 | 一次 10–20 分钟可接受，但**不许白跑** | 阶段 0 词族探针（0–3 次先验证假设） |
| 成本 | 没有硬上限，但**浪费要看得见** | `cost` 三字段 + `cost-log.jsonl` 账本 |
| 最不能忍 | ① 静默降级（以为是"没有"，其实是"没取到"）② 结论单边 ③ 重复劳动 | ① `status` 三值 + `degraded` ② 阶段 2.5 反证 ③ `exclude_topic` 增量 + `protocol` 落盘 |

**对这类用户，正确的优化方向是「去无效开销」，不是「简化输出」：**

* ✅ 阶段 0 的词族探针（3 次调用省掉一整轮无效广扫）
* ✅ `rest_preview`（一行摘要代替翻页，成本≈0）
* ✅ `exclude_topic`（第二轮不重扫已分析过的）
* ❌ 把结论压到 3 行（他要的是判断依据，不是标题）
* ❌ 跳过抽帧/ASR（这正是"理解透"的关键通道）

## 二、用户 B：企业级专业用户（潜在，尚未验证）

> ⚠️ **这一节是推演，不是实测**。四类场景来自 B 站作为"中文互联网特定人群样本池"
> 的商业用途推断，**没有真实客户验证**。落地前应向真实用户求证，别把它当需求文档。

### B1. 投研 / 咨询研究员

| | |
|---|---|
| **场景** | 行业或公司研究里需要「用户/公众在说什么」作为一手素材；尽调中的舆情面 |
| **买什么** | **可引用的证据**：一句话 + 出处 + 时间 + 可信度，能直接进脚注 |
| **最痛** | 二手报告口径混乱，转述三轮后找不到原始出处 |
| **本 skill 现状** | **适配度高**。每条事实带 BV + 时间戳 + 评级 + 交叉验证状态，已是脚注级 |
| **缺口** | ① 无引用格式导出（脚注/参考文献）② 无"同一结论跨平台交叉"（只有 B 站内部） |

### B2. 品牌 / 公关的舆情分析

| | |
|---|---|
| **场景** | 事件后的舆论**结构**分析：谁在说、谁占什么位置、争议焦点在哪、怎么被放大 |
| **买什么** | **结构**，不是情绪极性。常规舆情工具只给正/负/中，回答不了"为什么吵" |
| **最痛** | 极性分数无法指导动作；"负面 62%" 之后不知道该怎么办 |
| **本 skill 现状** | **适配度高**。阵营表（占据什么注意力货币）+ 冲突节 + 争议生产机制，正是"结构" |
| **缺口** | ① **时间序列**（事件演化、发酵曲线）② 预警阈值（什么信号算风险）③ 竞品/多品牌横向对比 |

### B3. 内容平台 / MCN 的运营与 BD

| | |
|---|---|
| **场景** | 评估某垂类的创作者生态、内容供给结构、赛道拥挤度、谁在涨 |
| **买什么** | **创作者与供给的地图**：关键节点是谁、同质化到什么程度 |
| **最痛** | 平台自有分析工具只看自家数据，看不到跨平台的舆论场 |
| **本 skill 现状** | **适配度中**。有 `get_creator_content`（档案/投稿/合集/动态）+ `videos.json`，能做单点画像 |
| **缺口** | ① 无粉丝增长/互动趋势（只有当前快照）② 无跨平台 |

### B4. 市场调研 / 用户研究

| | |
|---|---|
| **场景** | 把 B 站当作特定人群（Z 世代、二次元、技术爱好者）的**定性样本池** |
| **买什么** | **可辩护的定性结论**：样本怎么来的、偏差在哪、什么时候算够了 |
| **最痛** | 定性研究难复现、难规模化，客户会问"你怎么保证不是你挑的" |
| **本 skill 现状** | **适配度中高**。`protocol.md` 落盘 + 偏差声明 + `clusters.json` 已构成证据链 |
| **缺口** | ① **饱和判据**（什么时候算"再说也不出新东西"）② 样本人口学特征（B 站用户 ≠ 全体消费者） |

### 四类用户的共性（这才是企业化的真正门槛）

| 共性需求 | 现状 | 差什么 |
|---|---|---|
| **可复核** | ✅ `protocol.md` + `clusters.json` + `run-<日期>.json` | 无（D4 已补） |
| **可引用** | ✅ BV + 时间戳 + 评级 + 交叉验证状态 | 导出格式 |
| **可比较** | ❌ | 同议题多轮对比、多议题横向、竞品对比 |
| **可交付** | ⚠️ 有骨架 | 固定字段的机读导出（JSON/CSV），便于嵌进别人的系统 |

> **商业判断**：企业用户不为"分析过程"付费，为**「可交付的结论 + 可辩护的证据链」**付费。
> 所以企业化的关键不是加功能，而是把「判断的痕迹」变成**结构化、可导出、可对比**的数据。
> 这也解释了为什么 D4（clusters 落盘）比任何一个新取数工具都更重要。

### ⚠️ 与现有设计的一处冲突

`SKILL.md` 阶段 3 明确禁止「跨议题的 UP 主横向对比」，理由是"简报的目的是加深对**这一个议题**的理解"。
这条对**单议题深挖**是对的（防止跑题），但它同时挡住了 B1/B2/B3 最想要的"对比"能力。

**建议的解法不是改默认流程**，而是将来加一个独立的**对比模式**：
输入多个议题或多轮结果，输出"同一 UP / 同一阵营在不同议题上的表现漂移"。
默认流程保持纯净，对比作为显式的第二种产物。

## 三、按用户选参数（同一套工具，两种用法）

| 参数 | 自用型研究者（默认） | 企业级（推演） |
|---|---|---|
| `max_candidates` | 40 | 40–60（要更全的池子） |
| `comment_budget` / `comment_n` | 12 / 15 | 12 / 15（不变——质量优先） |
| `image_policy` | `hot` | `hot`（截图常是证据） |
| `offset` 翻页 | 看 `rest_preview` 决定 | 通常要翻 1–2 页 |
| `exclude_topic` | 第二轮必用 | 定期复跑必用 |
| 归簇回写 | 必须 | **必须**（这是他们买的"证据链"） |
| 抽帧 1080 | 只在核数字时 | 更常用（要引用画面里的数字） |
| 交付形态 | 对话内决策层 + 6 段证据层 + 按需存档 | 固定字段 + 可导出 |

## 四、这份画像怎么用

1. **做取舍时**：先问"这服务的是 A 还是 B"。
   对 A 是"去掉无效开销"，对 B 是"补齐证据链"——两者的动作不一样，别混。
2. **收到"太长了"的反馈时**：先确认是 A 的"无效开销"还是 B 的"结构不对"，
   不要直接砍内容。A 嫌长通常是"重复/废话"，B 嫌长通常是"没有分层"。
3. **不要为想象中的 B 改坏 A**。B 的四类场景是推演，A 是唯一被验证的用户。
